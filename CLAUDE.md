# dispatch

## Scripts are Go, not shell

Write every new script, hook or helper as Go, either as a `dispatch` subcommand or as its own small CLI under `cmd/`. Test it through its command line, following the `dispatch:surface-testing` skill's Go CLI pattern: `main()` is a thin wrapper around `Run(ctx, args, opts)`, and tests call `Run` or run the built binary.

Shell lets parsing logic hide where no test reaches it. The ticket hint hook once read `config.toml` with a 20-line awk program that re-implemented TOML string escapes, while the Go code already loaded the same file with `internal/config`. It is now `dispatch ticket-hint`, which reuses that loader and gets surface tests for free.

A file in `bin/` may stay a one-line shell wrapper that execs the Go binary, since plugins put `bin/` on the session PATH. Existing shell scripts move to Go when they are next changed.

## Testing

`make test` is the fast loop on the dev box, and `make test-race` adds the race detector for an occasional check. CI runs `make ci` (vet, `go test -tags tests_slow ./...`, shellcheck) without `-race`. The tag adds the tests tagged `tests_slow`: a test that takes over 1 second and cannot be made faster or run in parallel (the shipped rule scenarios, the cycle timing test, the 65 MiB history line). Both run against in-process fakes of the external tools (`internal/tooltest`). `make test-drift` (`go test -tags drift ./internal/...`) runs against the herdr, treehouse, gh and Claude installed on the machine and never against a GitHub or Linear account, so it needs no gh login and no Linear key and a failure means a fake or adapter drifted from an installed tool. It runs the same contract scenarios against the installed herdr and treehouse in a temp repo and pool root, and checks the flags dispatch passes to gh against the installed gh's `--help`. The gh fake holds GitHub's answers per branch and refuses to merge a pull request whose head moved. The Linear fake keeps tickets, statuses and comments in memory and `internal/linear/client_test.go` runs the real client against an HTTP test server to check the GraphQL wire format. It also delivers a follower message to a real Claude through its inbox (and checks one never answers an open question), and launches a worker on a real, logged-in Claude, once in a throwaway herdr session and once under the Herdr app host on a scratch herdr-core, and checks that the kickoff and a single-line and a multi-line slash nudge all record as sent by dispatch. The app run also checks that the `dispatch.session` label is the session id in Claude's transcript and that the worker's Stop lands in its Stop record. Each run spends a few short Claude turns. It fails when herdr, hc, treehouse, gh or `claude` is missing, and times out after 3 minutes when Claude is not logged in. CI never runs it, so run it after changing a fake or a real adapter.

`make test-claude` (`go test -tags claude ./internal/harness/`) runs six scenarios against a real, logged-in Claude Code worker on the Herdr app host, each on Haiku: launch, the plugin's hooks, the Stop hook's `background_tasks`, the Notification and UserPromptSubmit hooks, herdr's reading of the worker's status and session, and a delivered session message. Where `make test-drift` launches a real Claude to check dispatch's adapters, these check what Claude Code does inside a worker. They use a scratch herdr-core and a real dispatch over a scratch state dir. `internal/herdrtest/hooklog` sits in front of it on PATH and logs each hook payload, so the Stop scenario asserts the real Stop record and the wake scenario asserts the session log. They take about three minutes, CI never runs `make test-claude`, and each test fails if Claude's updater repointed `~/.local/bin/claude`. They cover the app host only; `make test-drift`'s TUI kickoff test covers the TUI host. They do not cover `dispatch watch` (the message scenario writes to the worker's socket directly), the workspace label, the Notification-to-loop wake, or the bypass-permissions dialog. They run against the real Claude config, logged in as you, because a scratch config dir logs Claude out. The worker's tree is one fixed directory, `dispatch-claude-live` under the temp dir, so trust is accepted once and later runs add nothing to `~/.claude.json`, and each test removes its transcript directory under `~/.claude/projects`. For the same reason the trust and bypass-permissions dialogs are not checked against real Claude, so a change to their wording is a known gap. The stand-in drift tests cover the launcher answering them.

They use the app host because it starts the program directly, so no launch command is typed into a shell and `Unrun` never applies.
